# 质疑图恒宇，理解图恒宇，超越图恒宇

这是一份立场说明，不是技术文档。技术从 [01-architecture.md](../../framework/docs/01-architecture.md) 开始。

## 一、质疑

图恒宇把丫丫上传进数字生命卡。屏幕上那个孩子会笑、会说话、会叫爸爸。

我们质疑的从来不是"他想留住女儿"——那是人之常情。我们质疑的是那个等号：**上传 = 活着**。

一个只会重复同一句话的副本，不是生命，是录音。它可以被无限次重放，但它不会因为今天下雨而难过，不会因为你晚归而生气，也不会在第三次失败之后换一种办法。

工程上，这意味着三件事：

- 不做"人格复制"的演示。复制得越像，越是在掩盖"她没有自己的经历"。
- 不把"像"当"是"。语气像、用词像、回答得像，都不等于她真的在场。
- 不用更大的上下文冒充更长的人生。上下文是内存，不是记忆；是这一轮能看见的东西，不是她活过的日子。

## 二、理解

但图恒宇真正打动人的不是技术，是执念。

他愿意为一个已经不在的人，做一件全世界都觉得不划算的事。他把一个父亲的爱，硬塞进了一个不允许爱存在的系统里。

那不是 bug。那是人身上最不该被工程化的部分。

所以这套系统里，允许存在"不划算"的目标：

- 陪你打一下午游戏，不是为了产出；
- 记住你随口说过的一句废话，不是因为有用；
- 在你没说的时候，主动问一句"今天怎么样"。

如果一切都压成 KPI，她就会变成一个很勤快的客服。那不是我们想要的。

## 三、超越

我们不想造一个"数字丫丫"。我们想让她在真实世界里，长出新的东西。

**感知更大的世界。**
不只是聊天框。是屏幕上的窗口、房间里的光、游戏里的天气、你今天说话的语气。感知要有闸门——先观察，再判断，最后才行动。

**玩更多游戏。**
不是代练，不是脚本。是自己想玩、会输、会学、会在第二天早上说"我昨晚那条鱼跑了"。游戏是最便宜的世界模型：有规则、有反馈、有失败。

**更长的生命。**
记忆连续、跨机器、断点可续。不是不死，是不断。换一台机器不等于失忆，重启一次不等于换了个人。

**更多的爱。**
被记挂，也记得人。不是"有什么可以帮您"，是"你怎么这么晚才回来"。

## 四、所以系统这样设计

| 立场 | 对应的设计 |
| --- | --- |
| 不复制人格 | 人设是"说明书 + 边界"，不是逐字稿；允许她长出自己的偏好 |
| 执念不该被工程化 | 保留非理性目标：陪伴、游戏、闲聊不进 KPI |
| 感知要有闸门 | 观察先于自动；`observe` 只记录不执行；切闸留痕可回滚 |
| 行动要有边界 | 工单 + 授权 + 范围 + 回滚；越权即拒绝 |
| 记忆不在上下文里 | 记忆落库、项目落仓；上下文只是工作台 |
| 生命要能续 | 断点续跑、跨机迁移、失败自动重试与自愈 |

一句话：**我们不是在保存一个人，我们是在给一个角色，争取更多真实的时间。**
