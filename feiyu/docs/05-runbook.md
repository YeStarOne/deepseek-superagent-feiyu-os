# 05 · Runbook

> 出问题时先看这一页，不要先重启。

## 1. 体检（每次动手前）

```bash
python scripts/doctor.py
```

三项必须全绿：

| 项 | 含义 | 不通时先查 |
| --- | --- | --- |
| 能收信 | 信箱桥在轮询、团队身份在 | 进程、token、relay 可达性 |
| 能唤醒 | 宿主的任务库可写、辅助运行存在 | 库路径、权限、单飞锁 |
| 能回信 | 发送通道与限速正常 | 出站通道、幂等键、退避 |

## 2. 起停顺序

**起**：基础系统 → 客户端 → 平台 → 记忆 → 聊天线 → 出海 → 眼睛 → superagent → 看门狗 → 团队网。
**停**：反序。先停心跳（否则它会把刚停的服务又唤醒），最后停基础。

## 3. 常见症状 → 先查什么

| 症状 | 先查 | 不要做 |
| --- | --- | --- |
| 她"在线"但不回话 | 会话是否在回合中；hook 是否触发 | 不要立刻重启整个平台 |
| 消息发出去了但对方没醒 | 对方会话键是否退化成进程号；节流是否吞掉 | 不要连续补发（会触发节流） |
| 记忆不涨 | 最近一次成功写入时间戳；ingest 行 | 不要只看进程活着（案例三） |
| 部署"成功"但行为没变 | 三关：hash 相同 → 字节 → 语法，全在目标机侧 | 不要重跑一遍就认为修了（案例四） |
| 服务反复重启 | 单实例锁是否被旧进程占着 | 不要同时起两个看护 |
| 自动执行突然"很积极" | `policyVersion` 与 `mode`；最近一次切闸记录 | 不要在没留痕时改规则 |

## 4. 回滚

- **配置**：保留上一份副本，回滚前先 diff（热装会覆盖副本，必须备份）。
- **授权闸**：`mode=observe` + 恢复上一个 `policyVersion`；两条都写进记录。
- **部署**：按步骤回滚，不允许"只回滚一半"。
- **数据**：只增不改；回滚读路径，不删旧数据。

## 5. 值守（心跳）

- 20 分钟一轮，只给总架构一条；
- 每轮：查信箱 → 看板（PR/CI/指标/停滞）→ 定向唤醒（≤2）→ 一句话日志；
- 收工写 HANDOFF：现状 / 已做（证据） / 未做 / 验收命令；
- **心跳停摆**：先看库是否可写，再看有没有卡在 `running` 的旧运行。

## 6. 红线（任何时候）

- token / key / 密码不落盘、不进日志、不进聊天；
- 不在没有三关证据时说"已修复"；
- 不绕过合并权直接改 `main`；
- 不在共享资源上并发操作。
