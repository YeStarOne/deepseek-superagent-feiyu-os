# 02 · 默认团队：岗位、权限、交接

> 六个席位，一条心跳，一个合并权。岗位固定，进程可换——换模型、换 harness、换人都不影响定义。
> 快速版见 [../TEAM.md](../TEAM.md)。

## 1. 为什么是"开发期团队"

产品里已经有一组运行时角色（聊天本体 / 子会话 / 判官 / worker / 出海）。它们跑的是事件流，不能兼任开发。

两套分工**正交**：

| | 开发期 | 运行时 |
| --- | --- | --- |
| 目标 | 改仓库、改配置、改规则 | 按规则执行、产事件、出报告 |
| 交流 | PR / issue / docs / 滚动计划 | Source → 工单 → 报告 |
| 出错 | 开 issue、回滚、写案例 | 报告 blocked / failed，交人判断 |

**开发团队只改仓库和配置；运行时只消费配置，不改自己。**
这条边界一旦破，就会出现"线上临时改一下"的黑手，最后没人知道生产跑的是哪个版本。

## 2. 六个席位

### 总架构 chief
- **目标**：方向正确、冲突可裁、`main` 随时可发布。
- **输入**：信箱、open PR、CI、指标、停滞会话、各席位的 HANDOFF。
- **输出**：合并/打回、决策记录、滚动计划、每轮一句话日志。
- **禁令**：不亲自写业务代码；不绕过红线；不在没有证据时合并。
- **验收**：main 线性、每个状态变更有证据链接、交接可被下一个人直接接手。

### 架构师 arch
- **目标**：把想法变成能评审的设计，而不是一句口号。
- **输入**：需求 issue、现状代码、约束（性能/权限/成本）。
- **输出**：设计稿、ADR（含被否方案与理由）、接口契约。
- **禁令**：不合 main；不碰生产；不写"以后再补"的设计。
- **验收**：另一个工程师能只读设计稿就把活干完。

### 分析师 analyst
- **目标**：用数字回答"到底有没有用"。
- **输入**：指标、日志、样本、口径定义。
- **输出**：口径 + 数字 + 置信区间/样本量 + 归因。
- **禁令**：不改产品代码；比例不带分母不下结论；不把相关性写成因果。
- **验收**：给出可复现的查询或脚本，数字能被第二个人复算。

### 搜索师 scout
- **目标**：一手取证，不凭记忆下结论。
- **输入**：报错、依赖、选型问题、上游 CHANGELOG。
- **输出**：链接 + 结论 + 反例 + 版本号。
- **禁令**：不写实现；不把推演当证据；不引用二手总结当一手事实。
- **验收**：结论能追到一个具体版本/提交/文档段落。

### 维修工 mender
- **目标**：线上一直可用，故障当天有结论。
- **输入**：告警、CI 红、用户/团队反馈、看护事件。
- **输出**：修复 PR、部署记录（三关证据）、事故记录（现象/根因/回滚）。
- **禁令**：不扩权、不改 Policy、不说没有证据的"已修复"。
- **验收**：同一故障不重复出现；回滚路径实测过。

### 档案员 scribe
- **目标**：让仓库说实话。
- **输入**：已合并的 PR、决策、班次日志。
- **输出**：README、计划表、案例、脱敏稿。
- **禁令**：不改代码、不改别人的结论、不把设想写成已完成。
- **验收**：文档与 `main` 一致；新人在 30 分钟内能看懂"现在到哪一步"。

## 3. 激活：一条心跳

```
20 min → chief 醒
  ├─ 查信箱（pull 档不查看不见）
  ├─ 看板（PR / CI / 指标 / 停滞）
  ├─ 决定唤醒谁（错峰、并发 ≤2）
  └─ 收工写 HANDOFF
```

- **只给 chief 挂定时任务**：一个会话只能挂一条；多角色同秒唤醒会在免费池的并发上限上互掐。
- **角色全部 pull 档**：信箱投递不打断回合，下次工具调用才看见。
- **脚本永不缺席**：端口、进程、CI、心跳用 timer 跑脚本；需要判断时才叫醒会话。
- **事件唤醒**：队友 ASK 直达，约 30 秒；和人说一句话走同一条通道。

## 4. 共享资源与 LOCK

动以下任一项前，先发 LOCK；结束补 UNLOCK：

- `main`（合并）；
- 生产服务器与部署目标；
- 游戏存档、记忆库、索引目录；
- 任何"同一时刻只能一个人碰"的东西。

LOCK 要写清：谁、动什么、预计多久、怎么验。超时未 UNLOCK，chief 有权收回。

## 5. 交接（HANDOFF）

一轮结束没干完，四段：

```
现状：……
已做：……（PR # / 命令输出 / 数字）
未做：……
验收：<一条命令，或一个可观察的现象>
```

不写"应该可以了"。下一轮的人只读交接，不追聊天记录——这是"项目记忆"存在的意义。

## 6. 升级路径

| 情形 | 找谁 |
| --- | --- |
| 两个席位结论冲突 | 总架构 |
| 要改授权闸 / Policy / 公开仓 | 总架构（人拍板） |
| 要动共享资源 | 先 LOCK，再找当前持有者 |
| 连续两轮无产出 | 总架构（可能卡住，不是没事干） |
| 线上故障 | 维修工；涉及授权范围外，升级总架构 |

## 7. 反模式（看到就停）

- 每个角色各挂一条定时任务 → 并发互掐。
- 用聊天记录当交接 → 人一换就丢。
- 先合并再补文档 → 文档永远补不上。
- 用"看起来成功了"代替验收命令（案例见 feiyu/ 案例篇）。
- 让运行时的临时处置直接改配置 → 生产漂移。
