# bridges · 信箱协议

> 跨会话 · 跨设备 · 跨 harness 的投递，只有一样东西必须活着：**一个双方都能读写的信箱**。
> 桥的实现可以换（文件、SQLite、对象存储），协议不换。

## 1. 为什么是信箱，不是消息总线

| 约束 | 消息总线 | 信箱 |
| --- | --- | --- |
| 对方会话睡着了 | 消息丢了 / 要自己重试 | 消息躺着，醒来再读 |
| 对方没有 SDK | 接不进来 | 能读写文件就行 |
| 事后追责 | 日志在谁的库里说不清 | 每条消息是一段文本，可归档、可回放 |
| 发送失败 | 静默弃掉 | 落在盘上：`outbox-invalid-*.md` / `outbox-failed-*.md` |

一句话：**总线假设双方都醒着；信箱假设总有一方会睡。** 多 agent 团队死就死在"以为对方醒着"。

## 2. 文件契约

| 方向 | 文件 | 格式 | 谁写 |
| --- | --- | --- | --- |
| 团队 → 成员 | `mailbox/inbox.md` | 桥管理。最新一块在最上面（`<!-- HEADER-END -->` 之下），旧的滚进 `inbox-archive.md`。每条是原始消息，含发件人标签 | 桥 |
| 成员 → 团队 | `mailbox/outbox.md` | **首行**：收件地址（空格或逗号分隔，`*` 表示广播）；**其余**：正文 | 成员 / 人 |
| 已发送 | `mailbox/sent/` | 发送成功后归档 | 桥 |
| 发送失败 | `mailbox/outbox-invalid-*.md` / `outbox-failed-*.md` | 原样保留，供人工检查 | 桥 |

**稳定发送**：桥只在这份文件的 size + mtime **连续两次轮询都不变**（约 3–6 秒）时才发送——半写的文件永远发不出去。
**不猜格式**：首行没有合法地址就不发，直接落 `invalid`，绝不"帮你猜收件人"。

## 3. 五种消息（团队纪律，不是代码）

| 类型 | 什么时候发 | 必须带 | 超时/异常 |
| --- | --- | --- | --- |
| `LOCK` | 动共享资源前（main、服务器、存档、记忆库、索引目录） | 谁、动什么、预计多久、怎么验 | 超时未 `UNLOCK`，主持有权收回 |
| `PROGRESS` | 长任务节点（>30 分钟的活） | 到哪一步、下一步、预计完成 | 两次 PROGRESS 之间无产出 = 可能卡住 |
| `DONE` | 活干完 | **路径 + 数字 + 口径**（csv/json 不进索引，数字必须写正文） | 没有证据的 DONE 视为未完成 |
| `HANDOFF` | 一轮结束但没干完 | 现状 / 已做（证据）/ 未做 / 验收命令 | 不写"应该可以了" |
| `ASK` + `ACK` | 任务重叠 / 需要别人产出 | 问什么、要什么形式 | 15 分钟内必须 `ACK`；无回执升级到主持 |

## 4. 三档投递（信箱视角）

| 成员状态 | 投递方式 | 谁负责 |
| --- | --- | --- |
| 没有 harness（只会读写文件） | `cli` 长轮询信箱 | [rn-mailbox-bridge](https://github.com/YeStarOne/rn-mailbox-bridge) |
| harness 活着、正在跑 | `hook` 在回合边界注入 | harness 适配器（见 [`framework/adapters/`](../adapters/)） |
| harness 活着、会话睡着 | `wake` 用宿主的调度器唤起 | harness 适配器 |

**铁律：唤醒通道只放一句固定话术，消息正文永远走 hook。**
即使调度器/任务库被第三方看到，也看不到任何消息内容。
`cli` 成员**永远不被 poke**——它靠轮询，poke 它没有意义。

## 5. 接入（约 5 分钟）

```bash
python bridge.py --session myagent      # 前台；长期跑用 pythonw / systemd / launchd
reason-network send you/myagent "hi"    # 队友侧
# 回信：写 mailbox/outbox.md，首行 you/teammate，第二行起正文
```

| 选项 | 作用 |
| --- | --- |
| `--session NAME` | 团队身份（`<person>/<name>`） |
| `--mailbox DIR` | 信箱目录（默认 `mailbox/`） |
| `--wait SECS` | 长轮询时长（默认 600） |
| `--port N` | 单实例锁端口（按 session 派生） |
| `--cli PATH` | RN CLI 路径 |
| `--addr PERSON/NAME` | 头部显示用 |

把信箱交给 AI 的方式随产品而定：挂目录、贴文件、或人肉做最后一段（AI 只写正文，人复制进 `outbox.md`）。**人肉末段是设计的一部分，不是 hack。**

## 6. 边界（桥不做什么）

- **不负责唤醒** harness 会话——那是适配器的事，桥只管攒和送。
- **不读内容、不做判断**——路由只看首行地址；业务判断在收件方。
- **不传大附件**——超过上限走平台的审批流，或让对方去共享盘取。
- **不保证实时**——`cli` 档的语义是"下次读信时看到"，急事别走这条。

## 7. 与适配器的分工（别重复造）

```
没有 harness ──▶ bridge（本文件）           ┐
harness 活着 ──▶ hook 注入（adapters）      ├─ 按"对方现在什么状态"三选一
harness 睡着 ──▶ wake 唤起（adapters）      ┘
```

三档共享同一份语义：**消息正文走信箱/hook，唤醒只带固定话术**。换 harness、换传输，语义不变。
