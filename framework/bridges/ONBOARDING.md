# 入队仪式（ONBOARDING）——新会话从「进程存在」到「编入团队」

> 信箱只投递给已存在的会话；**开一个新会话是各 harness 自己的活**（桌面手动开 / 已有会话换岗 / 未来的 spawn 原语，见 [SPAWN-PROPOSAL](../adapters/SPAWN-PROPOSAL.md)）。
> 但「开了」不等于「入编」——本文件定义新会话的第一条消息该做什么。任何 harness 通吃，没有专有依赖。

## 三步握手

1. **读**：`AGENTS.md`（红线与规矩）→ `TEAM.md`（六席与值班表）→ 你的角色卡（岗位说明书，`roles/<岗>/AGENTS.md`）
2. **认**：查一次信箱（按五类消息口径）；把自己的 todo 建好
3. **报**：向船长信箱发一条 `DONE` 自报家门（格式如下）

## 自报家门格式（复制改占位）

```
DONE · 入队：<席位名> 认领 <岗位>
- 已读：AGENTS / TEAM / 岗位卡
- 能力：<一句话——我能干什么，我不能干什么>
- 待命方式：<我会怎么被唤醒——心跳扇出 / 信箱 / automation>
- 首件事：<领取的第一件活，或「待命」>
```

船长收到后：把席位写进 `TEAM.md` 值班表、回复 `ACK`——入队完成。
**没有 ACK 就还不算入编**：15 分钟无回执，按信箱协议 ASK 升级。

## 复用改岗（没有 spawn 原语时的伪 spawn）

给一个已有的空闲会话投「换岗令」：角色卡换成新岗，然后照走三步握手。
纪律：旧岗的 todo 先清盘或移交（`HANDOFF`），再认新岗——**带病换岗是事故之源**。

## harness 差异注记

| harness | 怎么让新席位存在 |
| --- | --- |
| 桌面型（现状通用） | 桌面端新建会话 → 自动入网 → 人工投首消息走本仪式 |
| 已有会话换岗 | 自动化通道投换岗令（见上节），会话复用 |
| 未来 spawn 原语 | `spawn --name --prompt-file 角色卡` → 起来即入网即走本仪式（提案见 [SPAWN-PROPOSAL](../adapters/SPAWN-PROPOSAL.md)） |
| dsh 引擎 | session 由 profile 挂载，扩席 = 新挂载 + 本仪式 |

## 验收（「入队完成」的定义）

- [ ] 团队名单（RN `list_team` / 值班表）里能看到新席位
- [ ] 船长信箱收到 `DONE` 自报家门并已 `ACK`
- [ ] 席位 todo 已建、角色卡已挂、待命方式明确
