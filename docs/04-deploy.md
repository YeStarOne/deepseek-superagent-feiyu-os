# 04 · 部署：10 步

> 目标不是"跑个 demo"，是把整套系统装起来，并且**每一步都能单独重跑**。
> 十步之外没有魔法：每步都是"装一个东西 + 配一个东西 + 验一个东西"。

## 原则（三条，不可交易）

1. **幂等**：每一步重复执行结果相同；脚本自己判断"已装/未装"，不靠人记。
2. **失败即停**：`set -euo pipefail`；中途失败不带着半截状态往下走。
3. **自带验收**：每一步都要给一条可执行的验收命令。**"看起来成功了"不算。**

## 依赖图

```
01 基础系统（用户 / swap / 时区 / tailnet）
│
├── 02 OneBot 客户端 + 登录（需人工扫码）
│      │
│      └── 05 聊天线接线（反向 WS → 平台插件）
│
├── 03 平台 + web profile + 热装器
│      ├── 04 记忆引擎 + 空库 + 蒸馏/备份 cron
│      ├── 07 眼睛（eye-server + PC 桥 + 桌宠）
│      └── 08 superagent（orchestrator + 玩具源 + keeper）
│
06 出海通道（依赖 05）
09 看门狗（依赖 03–08）
10 团队网（依赖 08、09）
```

## 十步

### 01 · 基础系统
- **装什么**：专用用户、swap、时区、tailnet 客户端。
- **验收**：`tailscale status` 显示在线；`date` 时区正确；`swapon --show` 有输出。
- **回滚**：删用户与 tailnet 注册；swap 文件可删。

### 02 · OneBot 客户端 + 登录
- **装什么**：任意 OneBot 兼容客户端（容器或原生），开启反向 WS。
- **人工**：扫码登录（不可自动化；掉登录的恢复步骤写进 runbook）。
- **验收**：反向 WS 端口可连；客户端日志出现连接建立。
- **说明**：文档只教"接入任意 OneBot 客户端"，不绑定具体实现。

### 03 · 平台 + web profile + 热装器
- **装什么**：dsh 平台（npm）、`web` profile、插件热装器。
- **配置**：`deploy/cordis.patch.yml.example` → 复制为实配后填值；**配置真值不进仓**。
- **验收**：面板可达；热装器能装一个空插件并卸载。
- **回滚**：恢复上一份 profile 副本（热装会覆盖副本，先备份）。

### 04 · 记忆引擎 + 空库
- **装什么**：记忆图谱引擎（公开仓）、空库初始化、每晚蒸馏 cron、备份 cron。
- **验收**：写入一条测试记忆并检索回来；cron 有 `--dry-run` 输出。
- **自检**：**最近一次成功写入时间戳**必须在涨——不涨就是断档（案例三）。

### 05 · 聊天线接线
- **装什么**：平台插件（反向 WS → 会话）、人设卡模板、`AGENTS.md` 模板。
- **配置**：`templates/` 里的干净示例人设，**不要**用真实人设卡。
  - 完整人设卡骨架（规矩段 / 称呼与称谓 / 三类主动管道 / 亲密度条款 + 每节机制注）：[`templates/AGENTS.md`](../templates/AGENTS.md)
  - 只做人设的短版（soul / system 段注入）：[`templates/persona.md`](../templates/persona.md)
  - 项目治理用的 `AGENTS.md`（席位、边界、红线）：[`templates/project-AGENTS.md`](../templates/project-AGENTS.md)
- **验收**：发一条消息，收到回复；回合中插入第二条消息也能收到。
- **回滚**：停插件、切回上一份 session 配置。

### 06 · 出海通道
- **装什么**：outbox 服务（工单报告 → 私信）。
- **要求**：幂等键 = 报告 id；发送间隔 ≥8 秒（防风控）；免打扰时段可配。
- **验收**：一条测试报告真发到；重复投递不重复发。

### 07 · 眼睛
- **装什么**：`eye-server`（视觉笔记落盘）、PC 桥、桌宠（可选）。
- **要求**：节流去重；明确的"不看"契约；录屏有每小时上限。
- **验收**：`/health` 带 Bearer 通；一条笔记落盘且格式正确。
- **回滚**：停服务；笔记目录只增不改，可直接停用。

### 08 · superagent
- **装什么**：orchestrator、keeper（单实例看护）、玩具示例源、worker 人设注入。
- **要求**：先 `eval.mode=observe`，只记 `would_accept`；keeper 用文件锁保证单实例。
- **验收**：玩具源产出一条 `would_accept` 记录；手工 kill 进程后被 keeper 拉起；同时起两个 keeper 只有一个拿到锁。
- **回滚**：`mode=observe` + 停 keeper；工单可单独结束。

### 09 · 看门狗 + 健康检查 + 定时报告
- **装什么**：车道看护、掉线守护、每 10 分钟健康检查、每日 token 报表。
- **要求**：**脚本永不缺席**——timer 跑脚本，脚本只在需要判断时叫醒会话。
- **验收**：手工杀一个被看护的进程，30 秒内被拉起；报表文件当天生成。

### 10 · 团队网
- **装什么**：信箱桥（`rn-mailbox-bridge`）、relay 指向、值守 cron（20 分钟心跳）。
- **要求**：relay 用 tailnet 地址（零 DNS）；心跳只给总架构一条；角色保持 pull 档。
- **验收**：两个会话互相发信并收到；空闲会话能被叫醒（约 20–30 秒）；团队列表能看到 doing。

## 每步的脚本约定

```
install/NN-<name>.sh
  --dry-run      只打印将要做什么
  --yes          非交互
  退出码         0 成功 / 非 0 失败（失败即停）
  日志           stderr，单行前缀 [NN]
  验收           --verify 打印验收命令的真实输出
```

## 部署后必须做的三件事

1. `scripts/check-secrets.sh` 全仓扫描（含 QQ 号 / tailnet 段模式）；
2. 跑一次 `doctor.py`，三项全绿：**能收信 / 能唤醒 / 能回信**；
3. 写一条 `HANDOFF`：装到第几步、哪一步失败过、怎么验的。
