# 06 · 脱敏：开源前必须过的红线

> 公开前逐条打勾。任何一条没把握，就不发。
> 本文件写"规则与占位符"，**不写任何真值**。

## 1. 六类红线

| 类别 | 不许出现 | 处理 |
| --- | --- | --- |
| 密钥 | token、API key、密码、OAuth 文件、cookie | 全部走 env；仓里只有 `env.example` 的键名 |
| 身份 | QQ 号、群号、真实昵称、手机号、邮箱 | 占位符 `${BOT_QQ}` `${OWNER_QQ}` `${GROUP_QQ}` |
| 网络 | 内网/公网 IP、tailnet 主机名、端口映射 | 占位符 `${HOST_TAILSCALE}` `${HOST_PUBLIC}` |
| 路径 | 家目录、盘符、用户名 | `${WORKSPACE}` `${HOME}` 或相对路径 |
| 内容 | 对话原文、记忆数据、照片、说说素材 | 只出 schema 与空库初始化 |
| 语境 | 家庭关系、称呼、生活细节 | 不进开源文本 |

**永不开源**：真实人设卡、记忆与对话数据、客户端的具体获取与伪装细节（只教"接入任意 OneBot 客户端"）、池凭据、家庭语境。

## 2. 占位符约定

| 占位符 | 含义 |
| --- | --- |
| `${BOT_QQ}` | 机器人账号 |
| `${OWNER_QQ}` / `${PARTNER_QQ}` | 所有者 / 另一位使用者 |
| `${GROUP_QQ}` | 群 |
| `${HOST_TAILSCALE}` / `${HOST_PUBLIC}` | 服务器地址 |
| `${PC_TAILSCALE}` | 客户端机器地址 |
| `${WORKSPACE}` / `${HOME}` | 工作目录 / 家目录 |
| `${API_KEY}` / `${API_BASE}` | 模型凭据 |
| `${RN_RELAY}` | 团队 relay 地址 |

规则：**占位符可以出现在任何地方；值只能出现在 `.env`（并且 `.env` 在 `.gitignore` 里）。**

## 3. 发版前的四道闸

1. **扫描**：`scripts/check-secrets.sh`——密钥模式 + QQ 号段 + IP 段 + 家目录模式；0 命中才继续。
2. **逐条核对**：把本文件的六类红线逐条过一遍，每条写"已核对 / 无此项"。
3. **历史**：曾泄漏过凭据的仓，公开版必须走**全新历史**（orphan 单提交）。不要 `filter-repo` 后直接公开——旧对象仍可能被引用。
4. **人工确认**：由总架构给出一句明确确认后才公开；建仓与公开动作由同一个人执行，token 只在内存。

## 4. 允许保留的"工程结构"

这些不是隐私，公开反而有助理解：

- 目录结构与模块划分；
- 服务名、单元名、端口（在示例里用占位符）；
- 配置的**键名**与默认值（不含真实地址与凭据）；
- 错误信息、日志格式、验收命令。

## 5. 案例数字的处理

真实数字可以公开（PR 数、提交数、耗时、版本号），但：

- 不出现工单内容与业务数据；
- 不出现对话原文与个人称呼；
- 出处指向私有仓时写"私有仓"，不给链接。
