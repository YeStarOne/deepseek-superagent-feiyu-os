# 案例二 · 观察先于自动：4/4 对账后才敢切 auto

**时间**：2026-11-06 观察窗口 → 2026-11-07T10:31:26+08:00 切闸
**价值**：这是方法论，不是故事——任何"要不要放开自动执行"的团队都能直接抄。

## 问题

想让系统在没人看着的时候自己动手（回复、开单、执行）。
但模型会误判。直接切 auto，等于把误判写进生产，而且事后说不清"当时为什么这么判"。

## 做法

1. **`observe` 模式**：只记录 `would_accept`（如果放开，它会不会接），**不真开单、不执行**。
2. **人工复核**：把 `would_accept` 与人的判断逐条对照，按窗口对账。
3. **发现假阳性**：某一类事件在观察期里 **100% 是误判**。
4. **收紧规则文本**，而不是关掉整条源——源本身有价值，是规则太宽。
5. **切闸留痕**：把切闸时刻与 `policyVersion` 落盘，可一键回滚。
6. **切后回看**：确认 `kind` / `ticketId` 真的翻转了，不是"闸开了但没人执行"。

## 结果

- 4/4 窗口对账一致才切；
- 假阳性类别被规则挡住；
- 切闸有版本号与时刻，回滚有据。

## 证据

`policyVersion` 是面板 `GET /orchestrator/api/settings` 的顶层字段，算法：

```
key(POLICY_REVISION, JSON.stringify({ rules, mode, sources }))
```

真实链条：

| 阶段 | policyVersion |
| --- | --- |
| observe | `af4d20c7dd13…` |
| 禁规则（rev6） | `fc0ce03c2546…` |
| `mode=auto`（eval rev2） | `c3a7fa2f50f84eb69effc3ac0531ef1d` |

切闸时刻：`2026-11-07T10:31:26+08:00`。
出处：实现仓 `docs/history/2026-11-07-切闸记录.md`（私有仓）。

## 三个坑（写进检查单）

1. **`would_accept` 只验了准入，没验执行**——切完必须看真实 `kind` / `ticketId` 有没有翻转。
2. **比例判据必须带分母**——`n=0` 不算通过；"100% 准确"要写清样本量。
3. **信号与守门要分开**——两边都绿的断言没有鉴别力，不能拿来证明切换成功。

## 可复用点

任何"观察 → 自动"的切换都可以照这个模板：**只记录不执行 → 对人复核 → 收紧规则 → 留痕切闸 → 回看真实动作 → 留回滚**。
